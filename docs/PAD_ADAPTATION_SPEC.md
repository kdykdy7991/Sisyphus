# Sisyphus Pad 端适配实施方案

> 文档状态：可实施版本 1.1  
> 目标平台：OPPO Pad Mini（OPD2515，自用 APK，不涉及应用商店上架）  
> 适配范围：前端布局、触控交互、Tauri Android 运行与真机验收  
> 非目标：手机端专项设计、桌面端重构、功能重写、Google Play 发布

## 1. 结论与目标

当前项目是 React + Vite + Tauri 2，后端由 Rust、SQLite 和 Tauri Command 构成，技术栈可以继续复用，无需迁移到 Flutter 或 React Native。

本次适配应达到以下结果：

- OPPO Pad Mini 横屏（推荐使用姿态）下，首页、知识库、知识详情、图片导入、结果审核、对话和设置均可完整使用。
- OPPO Pad Mini 竖屏下，所有核心任务仍可完成，不允许依赖横向滚动查看被裁掉的界面。
- 桌面端现有视觉风格和信息架构保持不变。
- 支持手指和触控笔；连接键盘、鼠标时仍可正常操作。
- APK 安装后，SQLite 数据、模型配置、图片导入、对话和备份恢复均需经过真机验证。

## 2. 目标设备与验收视口

不要按照具体品牌判断设备，布局以 CSS viewport 宽度和输入方式为准。

已知目标设备参数：

- 设备：OPPO Pad Mini，入网型号 OPD2515。
- 屏幕：8.8 英寸 AMOLED，2520 × 1680，3:2，344 PPI。
- 系统：ColorOS 16。
- 物理分辨率不能直接作为 CSS 布局宽度。根据 Android 常见显示缩放推算，WebView 可能约为横屏 840 × 560、竖屏 560 × 840 CSS px；该数值仅用于制定保守断点，最终以真机读数为准。

应用首次在真机运行时必须记录以下值，并附在实施报告中：

```js
console.table({
  innerWidth: window.innerWidth,
  innerHeight: window.innerHeight,
  devicePixelRatio: window.devicePixelRatio,
});
```

| 场景 | CSS 视口参考 | 布局模式 | 优先级 |
|---|---:|---|---:|
| OPPO Pad Mini 竖屏 | 540–699px | 单栏 + 底部导航 + 抽屉 | P0 |
| OPPO Pad Mini 横屏 / 宽竖屏 | 700–899px | 紧凑双栏 | P0 |
| 大视口横屏 | 900–1100px | 标准双栏 | P0 |
| 小窗口保护 | 480–539px | 保护性单栏 | P1，不作为手机专项设计 |
| 桌面端 | 1101px 以上 | 保持当前布局 | P0，回归测试 |

建议至少使用以下尺寸进行浏览器模拟与真机复核：

- 840 × 560：目标设备推测横屏逻辑视口。
- 560 × 840：目标设备推测竖屏逻辑视口。
- 900 × 600：较小显示缩放下的横屏变体。
- 600 × 900：较小显示缩放下的竖屏变体。
- 540 × 720：最低 P0 宽度与软键盘场景。
- 480 × 720：小窗口保护场景。
- 1100 × 800、1280 × 800：桌面布局边界回归。

## 3. 全局适配策略

### 3.1 断点

沿用桌面优先的现有代码，新增四个内容驱动断点：

```css
/* 桌面：现有样式 */
@media (min-width: 1101px) { }

/* 大视口横屏：标准双栏 */
@media (min-width: 900px) and (max-width: 1100px) { }

/* OPPO Pad Mini 横屏 / 宽竖屏：紧凑双栏 */
@media (min-width: 700px) and (max-width: 899px) { }

/* OPPO Pad Mini 竖屏：正式单栏 */
@media (min-width: 540px) and (max-width: 699px) { }

/* 小窗口保护，不作为手机端正式设计 */
@media (max-width: 539px) { }
```

不要使用 User-Agent 判断平板。方向差异仅在确有需要时使用：

```css
@media (min-width: 540px) and (max-width: 899px) and (orientation: portrait) { }
```

### 3.2 移除硬性桌面宽度

当前 `src/styles.css` 中的以下规则是平板适配的首要阻塞项：

```css
body { min-width: 1100px; }
```

应改为：

```css
body { min-width: 0; }
#root { min-width: 0; }
```

所有页面容器都必须允许子项收缩，必要位置补充 `min-width: 0`。禁止用页面级 `overflow-x: auto` 掩盖布局问题；只有截图画布、代码块等本来就需要横向查看的局部区域可以横向滚动。

### 3.3 统一 Pad 变量

在 `:root` 中增加布局变量，避免各页面重复写魔法数字：

```css
:root {
  --sidebar-desktop: 238px;
  --sidebar-pad: 76px;
  --page-pad-x: clamp(20px, 3vw, 36px);
  --page-pad-y: clamp(24px, 3vw, 38px);
  --touch-target: 44px;
  --safe-top: env(safe-area-inset-top, 0px);
  --safe-right: env(safe-area-inset-right, 0px);
  --safe-bottom: env(safe-area-inset-bottom, 0px);
  --safe-left: env(safe-area-inset-left, 0px);
}
```

### 3.4 导航外壳

OPPO Pad Mini 横屏保留紧凑左侧导航，竖屏改为底部导航。两种形态复用同一份导航数据，禁止维护两套页面路由。

横屏（宽度 700px 以上）：

- 隐藏品牌文字，只显示品牌图标。
- 导航项改为“图标 + 短标签”上下排列，标签使用 11–12px。
- 隐藏侧栏底部引语。
- 每个导航项点击区域至少 64 × 52px，单个可点击目标不小于 44 × 44px。
- 选中状态必须通过背景或描边表达，不能只靠 hover。
- 左侧栏宽度控制在 72–80px，为主内容保留足够空间。

竖屏（宽度 540–699px）：

- 隐藏左侧栏，使用固定底部导航。
- 保留首页、知识库、导入、对话、设置五个入口，图标在上、短标签在下。
- 底部导航高度不含安全区时为 56–64px，并叠加 `env(safe-area-inset-bottom)`。
- 当前页面必须有明确选中状态；不得依赖 hover。
- `.main` 底部 padding 必须至少等于导航高度加底部安全区，防止正文和提交按钮被遮挡。

建议给 `Shell` 根节点增加语义明确的类，不必用 JavaScript判断屏幕：

```tsx
<div className="app-shell">
```

结构无需重写，主要通过 CSS 完成。Pad 下：

```css
.app-shell { grid-template-columns: var(--sidebar-pad) minmax(0, 1fr); }
.main { padding-bottom: var(--safe-bottom); }
```

竖屏底部导航需要调整 `Shell.tsx` 结构或增加同数据源的 `BottomNav` 组件，不能仅把现有 `<aside>` 旋转或绝对定位到底部。

### 3.5 安全区与 viewport

将 `index.html` 补为标准 HTML 结构，并设置：

```html
<meta
  name="viewport"
  content="width=device-width, initial-scale=1, viewport-fit=cover"
/>
```

Pad 横屏可能存在圆角、系统手势区或摄像头区域。侧栏、页面顶部和底部固定控件应叠加对应的 `env(safe-area-inset-*)`，不要直接给整个 `body` 重复 padding。

### 3.6 触控规则

- 所有按钮、图标按钮、列表行、标签删除按钮的实际点击区域至少 44 × 44px。
- 相邻图标按钮之间至少保留 8px 间距。
- 不得将关键能力只放在 `:hover` 中；保留 hover 仅用于鼠标反馈。
- 增加 `:active` 和 `:focus-visible` 状态。
- 拖放排序保留给鼠标，但图片列表必须同时提供“上移/下移”按钮，确保触摸设备可排序。
- 键盘快捷提示（如 `⌘ K`、`Enter 发送`）在纯触控环境下隐藏，连接精细指针/键盘时再显示。

```css
@media (pointer: coarse) {
  button, a, select { min-height: var(--touch-target); }
}

@media (hover: none) {
  kbd { display: none; }
}
```

## 4. 各页面具体改造

### 4.1 首页 `HomePage`

横屏：

- 页面左右 padding 缩至 28–36px。
- 900px 以上四个统计卡片可保持四列；低于 900px 固定改为 2 × 2。
- “最近阅读”和“值得回顾”保持双栏，但单栏宽度不得低于 360px。
- 最近列表隐藏领域/主题列或将其放到标题下方，避免五列同时争抢宽度。

竖屏：

- 统计卡片固定为 2 × 2。
- 最近内容改为上下单栏。
- 列表行使用“图标 / 标题与元信息 / 时间与箭头”三段式布局。
- 搜索结果弹层保持在搜索框容器内，最大高度 `min(60vh, 520px)` 并可滚动。

验收重点：最长问题标题不得把时间和跳转箭头挤出屏幕；统计差值文本允许换行或隐藏，不允许遮挡数字。

### 4.2 知识库 `KnowledgePage`

横屏：

- 主题栏从 270px 缩至 220–240px。
- 内容区 padding 缩至 24–32px。
- 列表最右侧的“领域 / 主题”允许隐藏，正文下方标签仍保留上下文。

竖屏：

- 将左侧主题栏改为页面顶部的筛选工具条。
- 工具条显示当前领域，并提供“选择领域”按钮；点击后打开左侧抽屉或底部面板。
- 抽屉宽度建议 `min(360px, 86vw)`，必须有遮罩、关闭按钮和 ESC/返回键关闭能力。
- 搜索框移动到知识列表标题下方并占满可用宽度。
- 知识列表行改为单列内容，不展示右侧冗余领域信息。

工程建议：该页面仅靠 CSS 隐藏 `topic-panel` 会丢失功能，需要在 `KnowledgePages.tsx` 增加 `filterOpen` 状态和一个 Pad 竖屏筛选入口。桌面与横屏继续复用现有 `topic-panel` 内容。

### 4.3 知识详情 `KnowledgeDetailPage`

横屏：

- 正文 + 右侧信息栏保持双栏。
- 右栏从 320px 缩至 260–280px。
- 正文标题使用 `clamp(28px, 3.2vw, 38px)`。

竖屏：

- 正文占满内容区，隐藏常驻右栏。
- 在顶部操作区增加“详情”按钮，打开右侧抽屉展示相关问题、所属主题、来源、备注与元数据。
- 顶部面包屑单行省略，至少保留返回“知识库”的按钮。
- 收藏、编辑、更多操作保持可触达；空间不足时只显示图标，并用 `aria-label` 提供名称。
- 编辑表单的“领域 / 主题”在目标设备竖屏固定为单列；横屏空间足够时可双列。

注意：备注若未来需要持久化，应与本次布局适配分开处理；本次不能改变其业务语义。

### 4.4 图片导入 `ImportPage` 上传阶段

- 文件选择按钮必须是主要入口，拖放文案降为辅助说明；Android WebView 上不能把拖放作为核心流程。
- `accept="image/*" multiple` 保留，真机验证系统图片选择器能否多选。
- 粘贴快捷键说明在无键盘环境隐藏。
- 上传列表删除、选择和排序控件满足 44px 触控区域。
- 增加显式上移/下移按钮；不要要求用户在触摸屏上使用 HTML5 drag-and-drop。
- 图片缩略图使用固定比例，文件名做省略，完整名称可在辅助文本或无障碍标签中获取。

### 4.5 图片处理阶段

- 当前进度列表固定宽度 480px，应改为 `width: min(480px, calc(100vw - sidebar - 48px))`。
- 页面需加安全区 padding，错误文本允许多行换行。
- “重试失败图片”和“放弃本批”保持清晰分层，不能只靠颜色区分。

### 4.6 提取结果审核阶段

这是本次改造量最大的页面。当前为“图片列表 + 原图 + 草稿”三栏，Pad 竖屏无法直接缩放使用。

横屏：

- 改为两栏主布局：左侧原图，右侧草稿。
- 图片列表从常驻第一栏移到左侧顶部的横向缩略图条，或通过“图片 2/5”按钮打开抽屉。
- 建议比例：原图 `minmax(280px, 0.8fr)`，草稿 `minmax(420px, 1.2fr)`。
- 顶部批量操作可保持，但按钮文案在窄宽度允许简化。

竖屏：

- 使用“原图 / 提取结果”两个分段标签，同一时刻只显示一个主面板。
- 当前草稿编号、上一条/下一条必须固定在内容顶部，切换标签时不能丢失草稿状态。
- “Pass / 确认入库”形成底部粘性操作栏，并计入底部安全区。
- 图片列表通过顶部“图片列表”按钮打开抽屉。
- 草稿表单所有字段在竖屏下单列；领域和主题仅在横屏且单栏可用宽度足够时双列。

需要在 `ImportPage.tsx` 增加：

- `reviewPane: 'source' | 'draft'` 状态。
- `imageListOpen` 状态。
- 横屏缩略图入口和竖屏分段控件。
- 触控排序按钮。

不能通过 CSS `order` 强行重排现有三栏完成全部交互，因为竖屏需要显式的面板切换状态。

### 4.7 对话 `ChatPage`

横屏：

- 保持对话 + 参考知识双栏。
- 右栏缩至 260–280px。
- 消息区左右 padding 调整为 28–48px。

竖屏：

- 对话占满内容区，右侧参考栏改为“参考知识”抽屉。
- 顶栏保留知识范围选择；“历史对话”和更多操作仅保留图标或收进溢出菜单。
- 输入框固定在页面底部、位于系统软键盘上方；使用 flex 布局和动态视口单位 `100dvh`，不要只用 `100vh`。
- 输入框获得焦点后，最新消息仍应可见，不得被软键盘覆盖。
- 用户消息最大宽度从 70% 调整为 82%；助手消息头像与正文布局保持。
- “Enter 发送”仅在检测到键盘/精细指针时显示。

建议将 `.chat` 高度改为：

```css
height: 100vh;
height: 100dvh;
```

### 4.8 设置 `SettingsPage`

- Pad 下隐藏右侧说明栏是合理的，说明内容若包含必要信息，应移动到对应设置分组内，而非直接丢失。
- 设置分组从“标题栏 + 表单栏”改为上下结构。
- 模型配置表单横屏可双列，目标设备竖屏固定为单列。
- 数据位置输入框与操作按钮可换行，路径允许省略但应可复制。
- 备份、恢复保持并排；清空知识库继续独占一行。
- 恢复确认弹层宽度使用 `min(520px, calc(100vw - 48px))`，按钮至少 44px 高。
- Android 文件选择器返回的 URI/路径语义必须做真机验证，不能只验证桌面路径。

## 5. Tauri Android 平台工作

### 5.1 初始化与构建

项目已经使用 Tauri 2，并且 Rust 入口已有：

```rust
#[cfg_attr(mobile, tauri::mobile_entry_point)]
```

建议工程师完成：

```bash
rustup target add \
  aarch64-linux-android \
  armv7-linux-androideabi \
  i686-linux-android \
  x86_64-linux-android

npm run tauri android init
npm run tauri android dev
npm run tauri android build -- --apk
```

自用真机可优先只构建 `aarch64`，减少构建时间与包体：

```bash
npm run tauri android build -- --apk --target aarch64
```

### 5.2 Android 专用配置

新增 `src-tauri/tauri.android.conf.json`，与桌面窗口配置解耦。建议至少覆盖：

- Android 显示名称和图标。
- `minSdkVersion`；Tauri 2 最低可使用 Android 7 / SDK 24，若个人设备版本较新可提高。
- 内容安全策略与远程 API 域名策略。
- 屏幕方向策略：建议默认支持旋转，不锁死横屏；横屏体验优先，但竖屏必须可用。

桌面配置中的 `minWidth: 1100`、`minHeight: 720` 属于桌面窗口约束，不应成为移动布局假设。

### 5.3 依赖与权限验证

逐项验证以下能力在 Android 上可编译、可运行：

| 能力 | 当前实现 | 验证重点 |
|---|---|---|
| SQLite | `rusqlite` bundled | 建库、迁移、FTS5/Jieba、重启后持久化 |
| 网络模型调用 | `reqwest` + rustls | Android 网络权限、HTTPS、自定义 API Base URL |
| 图片选择 | HTML file input | 相册多选、相机入口、HEIC/WebP/JPEG 大图 |
| Tauri dialog | `tauri-plugin-dialog` | Android 支持范围、返回 URI 是否能被 Rust 路径 API 使用 |
| 备份/恢复 | Rust 文件路径 | SAF/URI 兼容、读写权限、原子恢复与回滚 |
| 配置文件 | App data `config.json` | 重启持久化、卸载清除、API Key 不回显 |

备份/恢复是最大的平台风险。Android 系统文件选择器通常使用内容 URI；如果插件无法直接提供可供 `std::fs` 使用的普通路径，应改为以下任一方案：

1. 由前端/移动端插件读取选择结果为字节，再通过 Tauri Command 传给 Rust；或
2. 实现 Android 专用 Tauri 插件，使用 Storage Access Framework 读写文档流。

不要把全盘存储权限作为首选方案。

### 5.4 API Key 安全说明

现有实现将 Key 写入应用私有目录并在 Unix 上尝试设置 `0600`，对个人自用已有基础隔离，但不等同于 Android Keystore。第一版可保持现状，但应在文档中明确；后续若设备存在多人使用、Root 或备份同步需求，再迁移到安全存储插件。

## 6. 建议代码组织

不要把全部 Pad 规则继续追加为一整行 CSS。建议拆分：

```text
src/
  styles.css                 # 基础 token、桌面通用样式
  styles/
    tablet.css               # 540–1100px OPPO Pad Mini 规则
    touch.css                # pointer/hover/safe-area 规则
  components/
    ResponsiveDrawer.tsx     # 知识筛选、详情栏、参考知识共用
    SegmentedControl.tsx     # 审核页原图/草稿切换
```

组件规则：

- `ResponsiveDrawer` 必须支持标题、关闭按钮、遮罩点击、ESC/Android 返回键、焦点管理和 `aria-modal`。
- 不要为每个页面复制一套 drawer CSS。
- 断点尽量由 CSS 控制；只有“同一时刻显示哪个面板”这类状态性行为进入 React。
- 不建议在组件渲染中直接读取 `window.innerWidth`。确需 JS 媒体查询时封装 `useMediaQuery`，监听 `matchMedia` 变化并正确清理。

## 7. 实施顺序

### 阶段 A：基础框架（P0）

1. 修复 viewport、移除 `body min-width`。

## 9. 完成定义

满足以下条件才视为 Pad 端适配完成：

1. 已生成并安装可签名复用的 Android APK，而非只在浏览器响应式模式运行。
2. OPPO Pad Mini 真机横屏与竖屏全部 P0 流程通过，并记录实际 CSS viewport 与 DPR。
3. 无页面级横向滚动、关键操作遮挡或软键盘遮挡。
4. SQLite、模型调用、图片导入和备份恢复均在真机测试，而非仅桌面验证。
5. 桌面端回归通过。
