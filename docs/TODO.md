## 1. 知识库内容支持完整 Markdown 渲染

**现状**

- `src/pages/KnowledgePages.tsx` 的 `renderAnswer`（约 26 行）为“极简 markdown-ish
  渲染器”，仅处理：标题（`#`/`##`）、有序/无序列表、`\n\n` 空行分段、`\n` 换行。
- 明确**不引入** markdown 库，但模型输出受系统提示词约束，格式被刻意限制。

**目标**

- 知识条目的 `answer` 内容支持**完整 Markdown**：加粗/斜体、行内与代码块（```）、
  链接、表格、引用块、嵌套列表等。
- 建议方案（任选其一）：
  - 引入轻量库（如 `react-markdown` + `remark-gfm`）替换手写 `renderAnswer`，
    同时保留对 Vision 输出格式的兼容性；
  - 或扩展现有渲染器以覆盖上述语法，但需评估维护成本。
- 同时确认**存储层**（`db.rs` / 知识条目表）对长文本与特殊字符无长度或转义限制。

**验收**

- 一条含标题、列表、代码块、表格、链接、加粗的 `answer` 能正确渲染；
- 既有数据（旧格式）渲染不回归。

## 2. LLM 配置支持保存后切换（多配置，不覆盖旧的）

**现状**

- `src-tauri/src/config.rs` 的 `ApiConfig` 为**单份**结构，`save()` 直接覆盖
  `config.json`，内存态 `ApiConfigState` 也只持有一份。
- 没有“配置名/ID + 多份配置 + 当前启用项”的模型，因此新增一个配置会把旧的顶掉。

**目标**

- 引入**多份 LLM 配置（profile）** 的概念：每份含一个唯一标识/名称 + `ApiConfig`
  字段（baseUrl / key / chatModel / visionModel）。
- 支持：新增、保存、在已保存配置之间**切换**、删除（至少保留一份）、设置“当前启用”。
- 切换后即时生效：内存态与 `config.json`（或新的 `configs.json` / 索引文件）同步更新，
  且需与现有“空 key 视为保留原值”的合并逻辑兼容（避免切换时清空 key）。

**验收**

- 新增配置 B 后，配置 A 仍存在、可切回且字段完整；
- 切换配置后新对话使用所选配置的模型与地址；
- 配置含密钥，仍按既有 0600 权限落盘，不泄露到备份/同步（`.ikbackup` / `.iksync`）。
